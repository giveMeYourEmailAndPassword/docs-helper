# Roadmap: Telegram-бот для поиска информации в документах

## 1. Цель проекта

Создать Telegram-бота на Go, который позволяет пользователю загружать документы в форматах PDF и DOCX, а затем задавать вопросы по их содержимому.

Бот должен:

- принимать PDF и DOCX;
- извлекать и индексировать текст;
- искать релевантные фрагменты;
- формировать ответ через LLM;
- указывать документ, страницу или раздел, откуда взята информация;
- показывать несколько вариантов ответа, если документы противоречат друг другу;
- отображать промежуточные статусы: «изучаю документ», «ищу информацию», «формирую ответ».

---

## 2. Основной пользовательский сценарий

1. Пользователь запускает бота.
2. Загружает один или несколько PDF/DOCX-файлов.
3. Бот сохраняет документ и начинает обработку.
4. Пользователь получает статусы:
   - `📥 Документ получен`
   - `📖 Извлекаю текст`
   - `🧩 Разбиваю документ на фрагменты`
   - `🧠 Добавляю документ в базу знаний`
   - `✅ Документ готов к поиску`
5. Пользователь задает вопрос.
6. Бот показывает:
   - `🔎 Ищу информацию в документах`
   - `🤔 Сравниваю найденные факты`
   - `✍️ Формирую ответ`
7. Бот отправляет ответ с источниками.

---

## 3. Формат ответа

### Один источник

**Ответ:**  
Срок подачи заявления составляет 10 рабочих дней.

**Источник:**  
`Правила.pdf`, страница 12, раздел 3.2.

### Несколько совпадающих источников

**Ответ:**  
Срок подачи заявления составляет 10 рабочих дней.

**Источники:**
- `Правила.pdf`, страница 12;
- `Инструкция.docx`, раздел 4.

### Противоречащие друг другу источники

**В документах указаны разные варианты:**

1. Срок составляет 10 рабочих дней.  
   Источник: `Правила.pdf`, страница 12.

2. Срок составляет 14 календарных дней.  
   Источник: `Договор.docx`, раздел 5.1.

Бот не должен самостоятельно выбирать один вариант без предупреждения пользователя.

## 4. Архитектура

```text
Telegram
   ↓
Go Bot
   ↓
Загрузка PDF/DOCX
   ↓
Извлечение текста
   ↓
Разбиение на чанки
   ↓
Создание embeddings
   ↓
Vector DB
   ↓
Поиск релевантных фрагментов
   ↓
LLM
   ↓
Ответ + документы + страницы/разделы
```

---

## 5. Предлагаемый стек

- **Go** — Telegram-бот и основная backend-логика.
- **Telegram Bot API** — интерфейс пользователя.
- **PostgreSQL** — пользователи, документы, статусы обработки.
- **Qdrant** — хранение векторов и поиск по чанкам.
- **S3 / MinIO** — хранение оригинальных файлов.
- **OpenAI / Gemini / Claude** — embeddings и генерация ответа.
- **Docker Compose** — локальная разработка.
- **Dokploy** — деплой на VPS.

## 6. Основные сущности

### Document

- ID;
- владелец;
- название файла;
- формат;
- путь к файлу;
- статус обработки;
- количество страниц;

- ID;

- название раздела;

- итоговый ответ;
- использованные источники.

## 7. Этапы разработки

### Этап 1. Базовый Telegram-бот

- команда `/start`;
- обработка текстовых сообщений;
- загрузка файлов;
- вывод статуса обработки;
- базовое логирование.

### Этап 2. Обработка документов

- извлечение текста из PDF;
- извлечение текста из DOCX;
- сохранение страниц и разделов;
- обработка ошибок и пустых документов.

### Этап 3. Индексация

- очистка текста;
- разбиение на чанки;
- создание embeddings;
- сохранение чанков в Qdrant;
- привязка чанка к документу и странице.

### Этап 4. Поиск и ответы

- embedding вопроса;
- поиск 5–10 релевантных чанков;
- передача контекста в LLM;
- генерация ответа только на основе найденных данных;
- добавление источников.

### Этап 5. Работа с противоречиями

- группировка фактов по документам;
- сравнение найденных вариантов;
- обнаружение несовпадающих значений;
- вывод всех вариантов с отдельными источниками;
- запрет на смешивание противоречащих фактов в один ответ.

### Этап 6. UX

- сообщения «думаю», «ищу», «сравниваю»;
- редактирование одного статусного сообщения вместо спама;
- кнопка «Показать источники»;
- кнопка «Удалить документ»;
- команда `/documents`;
- выбор конкретного документа или всей базы знаний.

### Этап 7. Деплой

- Dockerfile для Go;
- Docker Compose для Go, PostgreSQL, Qdrant и MinIO;
- деплой через Dokploy;
- HTTPS и Telegram webhook;
- резервное копирование базы и файлов;
- лимиты на размер и количество документов.

---

## 8. MVP

Для первой версии достаточно:

- один пользователь;
- PDF и DOCX;
- загрузка нескольких документов;
- поиск по всем загруженным документам;
- ответы с названием файла и страницей;
- отображение разных вариантов при противоречиях;
- статусное сообщение во время поиска;
- деплой на Dokploy.

---

## 9. Возможные улучшения

- OCR для отсканированных PDF;
- поддержка TXT, XLSX и HTML;
- общие базы знаний для команд;
- роли и права доступа;
- веб-панель администратора;
- история вопросов;
- цитаты с точным фрагментом документа;
- повторная индексация после обновления файла;
- выбор LLM;
- кэширование повторяющихся вопросов;
- оценка уверенности ответа.

---

## 10. Главное правило системы

Бот должен отвечать только на основе загруженных документов.

Если информации недостаточно, ответ должен быть:

> В загруженных документах не найдено достаточно информации для надежного ответа.
